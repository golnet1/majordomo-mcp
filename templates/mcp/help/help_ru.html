Справка

Общие сведения

Модуль XiaoZhi MCP предназначен для поддержки навыков для платформы XiaoZhi AI. Модуль реализует авторизационный сервис на основе стандарта MCP — промежуточный API, который принимает запросы в формате MCP и преобразует их в запросы к API MajorDoMo.

Для успешного функционирования модуля и управления устройствами, подключёнными к MajorDoMo, через XiaoZhi AI требуется, во-первых, зарегистрироваться в сети Интернет и обеспечить тем самым их доступность со стороны облака XiaoZhi AI. Во-вторых, необходимо в консоли разработчика платформы XiaoZhi AI войти в раздел Configure Role → MCP Settings → Get MCP Endpoint и скопировать Endpoint URL в настройки модуля MCP (кнопка Настройки, поле Endpoint URL).

В модуле MCP все обработчики запросов реализованы с помощью Model Context Protocol (MCP) — универсального протокола для взаимодействия с ИИ.

В конечном итоге запуск модуля сводится к такой последовательности шагов:

  1. Установка модуля из маркета дополнений.
  2. Регистрация в XiaoZhi AI и получение Endpoint URL.
  3. Настройка модуля.
  4. Добавление устройств (вручную или синхронизацией из модуля «Устройства») и комнат.
  5. Проверка окружения Python (при необходимости — автоисправление).

Верхняя панель модуля содержит: Настройки, Синхронизировать (перенос устройств из модуля «Устройства»), Добавить смартфон, Добавить устройство, ссылку на консоль XiaoZhi, Сцены, Планировщик, блок Сервис, а также Справка и О модуле.

Настройки модуля
Endpoint URL Адрес вида wss:// вместе с токеном, полученный на странице MCP Endpoint конфигурации XiaoZhi. Без него модуль не сможет подключиться к облаку XiaoZhi AI.
Представление Стиль отображения списка устройств на главной странице модуля: Таблица, Таблица с группировкой, Панели, Панели с группировкой (варианты с группировкой группируют устройства по расположению).
Проверка версии Python и зависимостей При включении модуль проверяет интерпретатор виртуального окружения и его версию (не ниже 3.10), библиотеки из lib/requirements.txt и права на запуск скриптов окружения. При несоответствии выводится предупреждение и кнопка автоисправления (см. раздел «Окружение Python»).
Отладка DebMes Записывать подробную отладочную информацию в журнал MajorDoMo. Значок списка рядом с флажком открывает окно со служебной информацией модуля.
Включать в лог ping-запросы Записывать периодические ping-запросы к облаку XiaoZhi (удобно при диагностике связи).
Яркость без диммера Что делать, если просят яркость (например, «свет на 30%»), а устройство не поддерживает регулировку:
  • Сообщить, что устройство не поддерживает яркость — команда не выполняется, ассистент сообщает, что яркость недоступна (режим по умолчанию);
  • Включить на 100% и предупредить — устройство включается на полную мощность, а ассистент предупреждает, что яркость не поддерживается.

После сохранения настроек мост модуля перезапускается автоматически, чтобы новые значения вступили в силу.

Устройства и комнаты

Устройства добавляются кнопкой Добавить устройство (значок «+») и отображаются на главной странице модуля. Кнопка Добавить смартфон (значок телефона) формирует MAC-адрес и код активации для приложения XiaoZhi на Android.

Синхронизация с модулем «Устройства». Кнопка Синхронизировать (значок обновления, в верхней панели сразу после Настройки) переносит устройства из штатного модуля «Устройства» MajorDoMo (таблица devices) в модуль MCP. Переносятся все устройства, кроме кнопок (button), архивных и не привязанных к объекту MajorDoMo: тип MCP и умения определяются по типу и названию устройства в «Устройствах», а свойство объекта подбирается из числа фактически существующих у связанного объекта (сам объект и его классы). Название устройства автоматически попадает в синонимы. Повторный запуск безопасен — уже добавленные устройства (по связанному объекту) не изменяются и не дублируются; по завершении выводится отчёт «добавлено / уже было / пропущено».

Поля устройства:

  • Название — как устройство подписано в модуле и отображается в списке и на панелях. Участвует в работе: при синхронизации из модуля «Устройства» название попадает в синонимы, а задания планировщика определяют устройство именно по названию.
  • Синонимы — слова и фразы, которыми пользователь называет устройство голосом. Можно указать несколько через запятую или точку с запятой; регистр и порядок слов не важны.
  • Тип — свет, розетка, переключатель, шторы/жалюзи, дверь/ворота/окно, телевизор, ТВ-приставка, AV-ресивер, Колонка (XiaoZhi), кондиционер, термостат, чайник, пылесос, датчики и другие.
  • Расположение — комната или место (список берётся из MajorDoMo). Используется для группировки и для уточнения «в какой комнате».
  • ID устройства — только для типа Колонка (XiaoZhi): ID колонки, по которому модуль понимает, из какой комнаты пришла команда. Как заполнить и получить ID — в разделе «Колонка (XiaoZhi) и комнаты».
  • Описание, Производитель, Модель, Версия ПО, Версия АО — справочные сведения об устройстве.
  • Характеристики (умения и датчики) — что устройство умеет (включение/выключение, яркость, цвет, открытие, пауза и т. п.) и какие датчики у него есть (температура, влажность, движение и т. п.). Для каждого указываются связанный объект и свойство MajorDoMo: при ручном добавлении — вручную, при синхронизации — подбираются автоматически. Для типа «Колонка (XiaoZhi)» это поле не обязательно.
  • Реверс — значок со стрелками рядом с умением включения. Инвертирует смысл «Вкл/Выкл» (а также «Открыть/Закрыть»): нужно, когда реле управляет устройством с обратной логикой.

Если синоним содержит слово, похожее на тип устройства (например, «окно» в синониме «Свет над окном»), модуль всё равно находит устройство по его синониму: явное совпадение по синониму имеет приоритет над догадкой о типе.

Колонка (XiaoZhi) и комнаты

Привязка колонки к комнате позволяет выполнять команды, сказанные этой колонке, в её комнате без названия комнаты — просто «включи свет», и свет включится в комнате этой колонки. Без привязки работает так: комната уточняется голосом, а из колонки команды идут по общим правилам.

Что нужно:

  • устройство типа Колонка (XiaoZhi) с заполненными Местоположением (комнатой) и ID устройства — без них комнату определить не удастся; Характеристики для колонки заполнять не нужно (при необходимости достаточно одной — «Громкость»; пауза и режим без звука не используются);
  • ID устройства — номер колонки в xiaozhi.me: его можно вписать вручную или получить кнопкой «Определить колонку» (см. ниже).

Кнопка «Определить колонку». Кнопка находится рядом с полем ID устройства и видна только пока поле пустое. Нажмите её и в течение 10 секунд скажите этой колонке: «Определи колонку» или «Определи ID». Колонка назовёт свой ID, он появится в поле — затем нажмите «Сохранить». Если за 10 секунд колонка не ответила, нажмите кнопку ещё раз и повторите фразу.

Если ID уже занят. Если такой ID уже используется в модуле, модуль не запишет его и при автоопределении колонка ответит «колонка уже определена в комнате: …» — поле останется пустым. Также нельзя сохранить вручную уже занятый ID. Используйте другой ID.

Пошагово:

  1. Добавьте устройство типа «Колонка (XiaoZhi)»: укажите Название, Синонимы и Местоположение (комнату) и сохраните.
  2. Оставьте поле ID устройства пустым и нажмите «Определить колонку» — включится режим ожидания (до 10 секунд, с обратным отсчётом на кнопке).
  3. Скажите этой колонке: «Определи колонку» или «Определи ID». Колонка назовёт свой ID, и он автоматически появится в поле — затем нажмите «Сохранить».

Команды другой колонке (озвучка, громкость, вкл/выкл). Колонка XiaoZhi сама подключается к модулю, поэтому «толкнуть» в неё звук снаружи нельзя. Фраза или команда для другой колонки выполняется одним из способов: напрямую — если в настройках модуля указан HTTP-мост управления колонками (свой xiaozhi-сервер или шлюз) или у колонки в MajorDoMo привязан объект-озвучка; иначе команда ставится в очередь и выполняется колонкой, когда в неё в следующий раз что-то скажут — ассистент получит её вместе с ответом и произнесёт текст или изменит громкость. «Выключить колонку» означает громкость 0 (отдельного питания у колонки нет), «включить» — вернуть обычную громкость.

Голосовое управление

Примеры голосовых команд:

  • Свет, розетки, переключатели: «включи свет над окном», «выключи боковой свет», «зажги нижний свет».
  • Яркость: «включи нижний свет на 30%», «яркость 70». Для устройств без диммера действует настройка Яркость без диммера.
  • Групповые команды: «включи весь свет в большой комнате», «выключи свет везде», «выключи всё на кухне».
  • Шторы, ворота, окна: «открой шторы», «закрой ворота», «открой на 50%».
  • Термостаты и кондиционеры: «включи кондиционер», «поставь 24 градуса», «режим охлаждения».
  • Датчики: «какая температура на балконе», «какая влажность в бане», «какое освещение». Если в комнате несколько датчиков, модуль выбирает нужный по названной величине (влажность/температура/давление и т. п.) — даже когда ассистент передаёт только комнату и единицу измерения.
  • Сцены: «запусти сцену Вечеринка», «включи сцену …».
  • Передача фразы на колонку: «передай на колонку в кухне: обед готов», «скажи в спальне, что я пришёл». Фраза прозвучит на колонке в указанной комнате.
  • Громкость и питание колонки: «сделай громче колонку в кухне», «поставь громкость 30 в спальне», «выключи колонку в комнате отдыха».
  • Планировщик: «включи свет на кухне в 7:30», «выключи через 15 минут», «каждый день в 22:00 выключай весь свет», «покажи задания планировщика».
  • Скрипты MajorDoMo: «запусти сценарий …».

Если команда неоднозначна, ассистент попросит уточнить комнату (с указанием списка комнат) или устройство (с указанием подходящих устройств).

Сцены (группы)

Сцены (группы) — это наборы действий над устройствами, которые выполняются одной командой. Открываются кнопкой Сцены.

  • У сцены есть Название, Синонимы (по ним сцена вызывается голосом) и список действий: для каждого устройства — действие (включить/выключить), яркость и т. п.
  • Сцену можно временно отключить флажком Включена — тогда она не выполняется.
  • Голосом: «запусти сцену Вечеринка». Также доступны создание сцены, переименование, добавление и удаление устройств, включение/отключение и удаление сцены.
Планировщик задач

Планировщик задач открывается кнопкой Планировщик. Каждое задание содержит:

  • Описание и Время срабатывания;
  • Повтор: одноразово, по дням недели или с датой;
  • Устройство, Действие и, при необходимости, Яркость, %;
  • флажок Включено — временно отключить задание.
  • Можно создавать задания на конкретное время, ежедневные, по дням недели, а также разовые «через N минут».
  • Голосом: «включи свет на кухне в 7:30», «каждый день в 23:00 выключай весь свет», «через 20 минут выключи нижний свет», «покажи задания планировщика», «удали задание …».
  • При голосовом создании задания устройство подставляется автоматически, и его можно проверить или поправить в списке заданий.
Окружение Python

Настройка Проверка версии Python и зависимостей включает проверку окружения модуля:

  • наличие интерпретатора python3 и launcher-скрипта pip3 в каталоге lib/.venv;
  • версия Python не ниже 3.10;
  • установленные библиотеки из lib/requirements.txt;
  • права на запуск скриптов окружения.

Если найдены несоответствия, появляется кнопка «Исправить версию Python и зависимости». Она:

  1. подбирает подходящий интерпретатор Python (не ниже 3.10);
  2. при необходимости пересоздаёт виртуальное окружение (старое удаляется только после успешного создания нового);
  3. восстанавливает права на запуск файлов в .venv/bin;
  4. устанавливает зависимости из requirements.txt;
  5. перезапускает мост модуля.

Результат выводится списком шагов с отметками «выполнено» (зелёная галочка) или «ошибка» (красный крестик). Для автоисправления у веб-сервера должны быть права на запись в каталог модуля.

Диагностика
  • Значок списка рядом с флажком Отладка DebMes открывает окно Служебной информации: Endpoint URL, флаги отладки, представление и текущий режим Яркость без диммера (в виде понятного описания).
  • Блок Сервис в верхней панели управляет циклом модуля (запуск, остановка, перезапуск моста).
  • Кнопка О модуле показывает сведения о версии и авторе.
  • При проблемах со связью включите Отладка DebMes и Включать в лог ping-запросы и смотрите журнал MajorDoMo.
